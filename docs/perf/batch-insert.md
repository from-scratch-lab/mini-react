# 연속 삽입 묶기 · 전체 지우기 한 번에

## 문제

빈 `<tbody>`에 1,000행을 그리면 diff는 CREATE 패치 1,000개를 만들고, patch는 `insertBefore`를 1,000번 불렀다.
지울 때도 REMOVE 1,000개 → `remove()` 1,000번. MutationObserver로 보면 DOM이 1,000번 바뀌었다고 알린다.

또 diff는 자식을 **뒤에서부터** 처리한다(새 노드를 넣을 자리 "바로 뒤 형제"가 항상 이미 제자리에 있게 하려고).
그래서 빈 `<select>`에 option a·b·c를 만들면 c가 먼저 들어가 선택되고, 처음부터 그린 화면(a 선택)과 달랐다(B6, mr-dx 발견).

## 바꾼 것 (patch 단계만, 패치 목록은 그대로)

- **연속 CREATE 묶기**: 같은 부모에, 각 패치의 `before`가 바로 앞 패치에서 만든 노드인 CREATE들은 한 덩어리다.
  이들을 **앞에서부터** `DocumentFragment`에 만들어 붙이고, 덩어리의 맨 뒤 형제 앞에 `insertBefore` 한 번으로 넣는다.
  - 노드는 진짜 부모를 기준으로 만든다. `createDom`이 부모의 네임스페이스로 SVG 여부를 정하기 때문이다(빈 `<svg>`에 도형을 만들 때).
  - 앞에서부터 넣으므로 B6이 같이 고쳐진다.
  - 만들다 실패하면 fragment만 버려지고 실제 DOM은 그대로다.
- **전체 지우기**: 이어지는 REMOVE들이 한 부모의 실제 자식을 **전부** 지우면 `textContent = ''` 한 번으로 비운다.
  - "실제 자식 수(`childNodes.length`) = 지울 노드 수"일 때만 쓴다. Phase 1처럼 HTML을 attach로 읽은 트리에는
    가상 트리에 없는 들여쓰기 공백 텍스트가 남아 있어서, 그때는 지금처럼 하나씩 지워 공백을 남긴다.
  - `<textarea>`(텍스트가 기본값)와 `<template>` content(요소가 아님)는 묶지 않는다.
패치 목록이 같으니 학습 페이지의 패치 설명·개수, 기존 테스트의 의미가 바뀌지 않는다.

## 결과

`docs/benchmarks.md` "개선 기록 2" 참고. 요약:

- DOM 변경 기록: 생성·덧붙이기·지우기 1000 → 1, 전체 교체 2000 → 2.
- 브라우저 시간: 지우기 약 14% 빠름, 넣기는 차이 없음. jsdom에서는 지우기가 오히려 느리다.

### 왜 브라우저 시간은 거의 그대로인가 (학습 포인트)

"DOM 조작은 느리다"의 대부분은 **레이아웃(Reflow)과 페인트**다. 브라우저는 DOM이 바뀔 때마다 레이아웃을 바로 계산하지 않고,
"다시 계산해야 함" 표시만 해 두었다가 화면을 그리기 직전이나 스크립트가 `offsetHeight`처럼 레이아웃 값을 읽을 때 한 번 계산한다.
그래서 노드를 1,000번 넣어도 중간에 레이아웃 값을 읽지만 않으면 레이아웃은 한 번이다. Fragment로 묶어서 줄어드는 것은
삽입 호출과 변경 기록 같은 작은 비용뿐이다.

반대로 넣을 때마다 레이아웃 값을 읽으면(강제 동기 레이아웃, layout thrashing) 1,000번 계산하게 된다. 이것이 진짜 느린 경우다.
가상 DOM이 하는 일은 "읽기와 쓰기가 섞이지 않게, 바뀐 것만 한꺼번에 쓰기"이고, 이 구현의 patch도 쓰기만 하고 레이아웃을 읽지 않는다.

## 실제 React·Vue는?

| | 이미 있는 빈 부모에 목록 그리기 | 목록에 덧붙이기 | 전부 지우기 |
|---|---|---|---|
| React 18 | 행마다 `appendChild` (부모까지 새로 만드는 경우에만 화면 밖에서 다 만든 뒤 맨 위 노드 하나를 붙인다) | 새 행마다 `insertBefore`/`appendChild` | 행마다 `removeChild` |
| Vue 3 (가상 DOM 모드) | 행마다 삽입 | 행마다 삽입 | 행마다 제거 (텍스트 자식으로 바뀔 때 등 일부 경로만 한 번에) |
| 이 구현 | fragment 한 번 (이전 트리가 없으면 원래도 하위 트리째 하나) | fragment 한 번 | 자식 전부면 `textContent = ''` 한 번 |

Vue의 vapor 모드 `v-for`, Inferno·ivi 같은 라이브러리는 목록 전체를 지울 때 `textContent = ''` 빠른 경로를 쓴다.
React·Vue(가상 DOM 모드)가 행마다 넣는 것도 위와 같은 이유(레이아웃은 어차피 한 번)로 큰 손해가 아니기 때문이다.
