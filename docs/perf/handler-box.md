# 핸들러 교체를 패치에서 빼기

## 문제

컴포넌트는 렌더할 때마다 처음부터 다시 실행된다. 그래서 `onClick: () => remove(row.id)` 같은 화살표 함수도 렌더마다 **새 함수**다.
diff는 속성을 `Object.is`로 비교하므로 이 함수가 "바뀌었다"고 보고 PROPS 패치를 만들었다.

1,000행 표(행마다 핸들러 2개)를 같은 데이터로 다시 그리면:

- 패치 2,000개
- 실제 DOM 변경(MutationObserver 기록) 0개

patch는 이 PROPS를 받아도 DOM을 바꾸지 않는다. 리스너는 요소마다 이벤트 종류별로 한 번만 달려 있고(`setEventHandler`),
리스너가 부를 함수만 표에서 바꾸기 때문이다. 즉 2,000개 전부 "DOM을 바꾸지 않는 패치"였다.
종합 데모의 패치 목록이 이 소음으로 가득 차서, "바뀐 부분만 고친다"는 설명과 숫자가 어긋났다.

## 바꾼 것

- `diff`: on* 속성이 **함수 → 다른 함수**로만 바뀌면 PROPS에 넣지 않고, 결과 배열의 `handlers`(열거되지 않는 속성)에
  `{ vnode, name, value }`로 담는다. 같은 함수면 아무것도 담지 않는다.
- `patch`: 모든 DOM 패치를 마친 **뒤에** `handlers` 목록대로 요소의 핸들러 표만 갈아 끼운다.
- 그대로인 것: 핸들러를 새로 달기(없음 → 함수), 떼기(함수 → 없음), 문자열 인라인 핸들러와의 전환은 지금처럼 PROPS다.
  이때는 리스너를 달거나 속성을 지우는 일이 실제로 있기 때문이다.

### 왜 patch가 끝난 뒤에 갈아 끼우나

`render()`·컴포넌트 경로는 patch가 실패하면 `commitTree`의 `restore`가 실제 DOM을 다시 읽어 직전 트리와 맞추고, 이때 핸들러도 다시 단다.
하지만 Phase 1 페이지와 벤치처럼 `diff`·`patch`를 직접 쓰면 이 되돌림이 없다. 핸들러를 PROPS 순서대로 먼저 바꿔 두면
뒤쪽 패치가 실패했을 때 DOM은 반쯤 바뀐 채인데 핸들러는 이미 새 렌더 것이 된다. 모든 DOM 패치가 성공한 뒤에만 갈아 끼우면
어느 경로에서든 핸들러가 DOM보다 앞서 가지 않는다.
(테스트: `tests/diff/handlers.test.js` "되돌림 없이 diff·patch를 직접 써도…", 이 테스트는 바꾸기 전 코드에서는 실패한다)

### 왜 `handlers`를 열거되지 않게 붙였나

diff 결과는 지금까지 "패치 배열"이었고, 테스트·데모가 이 배열을 그대로 비교하고 순회한다.
열거되지 않는 속성이면 `toEqual`·`for…of`·`map`에는 보이지 않으니 기존 사용처가 그대로 동작한다.

## 결과 (1,000행)

| 시나리오 | 패치 전 → 후 | DOM 변경 기록 |
|---|---|---|
| 같은 데이터 다시 렌더 | 2000 → 0 | 0 (그대로) |
| 10행마다 갱신 | 2100 → 100 | 100 (그대로) |
| 한 행 선택 | 2001 → 1 | 1 (그대로) |
| 두 행 swap | 2002 → 2 | 4 (그대로) |

시간은 diff 5~18%, patch 30~40% 줄었지만 측정 흔들림보다 작아 주장하지 않는다. 이 개선의 가치는 **패치 목록이 실제 변경만 보여 준다**는 데 있다.
자세한 수치: `docs/benchmarks.md` "개선 기록".

## 실제 React·Vue는?

| | 핸들러가 렌더마다 새 함수일 때 |
|---|---|
| React | 핸들러를 DOM에 달지 않는다. 루트 컨테이너에 이벤트 종류마다 리스너를 하나씩 달고(이벤트 위임), 이벤트가 나면 대상 요소의 fiber에서 **지금 props**를 읽어 핸들러를 찾는다. 그래서 핸들러가 바뀌어도 DOM 작업이 없다. |
| Vue 3 | 요소마다 `invoker` 함수를 리스너로 한 번 달고, 핸들러가 바뀌면 `invoker.value`만 바꾼다. 이 구현과 가장 비슷하다. |
| 이 구현 | 요소마다 이벤트 종류별 리스너 한 번 + 핸들러 표(`setEventHandler`)는 원래 있었다. 이번에 바꾼 것은 그 표를 갈아 끼우는 일을 "패치"로 세지 않는 것이다. |

React처럼 이벤트 위임까지 하면 생성할 때의 `addEventListener` 호출(1,000행에 2,000번)도 사라지지만,
focus·blur처럼 버블링하지 않는 이벤트와 `stopPropagation` 순서를 따로 처리해야 해서 측정으로 이득을 확인한 뒤에만 한다(ADR 0001).
